Les URLs canoniques : à quoi ça sert ?

1 Accroche

Indiquer la version principale quand plusieurs URL donnent accès au même contenu

Imagine que ton site propose une fiche produit. Tu peux accéder à cette fiche avec : https://exemple.fr/chaussures. Mais ton site possède aussi des URL avec des paramètres : https://exemple.fr/chaussures?couleur=rouge ou https://exemple.fr/chaussures?tri=prix ou encore https://exemple.fr/chaussures?utm_source=newsletter.

Pour l'utilisateur, il s'agit toujours de la même fiche produit. Mais pour un moteur de recherche, ce sont des URL différentes. Alors quelle URL doit être considérée comme la version principale ?

C'est précisément le problème auquel répond la balise canonical.

3 Le concept expliqué simplement

Qu'est-ce qu'une URL canonique ?

Une URL canonique est l'URL que tu considères comme la version principale d'un contenu lorsque plusieurs URL peuvent donner accès à des contenus identiques ou très similaires.

La balise correspondante ressemble à ceci :

📄 code.html
<link rel="canonical" href="https://exemple.fr/chaussures" />

Elle se trouve généralement dans la partie <head> de la page. Elle indique notamment aux moteurs : « Parmi les différentes URL qui peuvent représenter ce contenu, voici celle que je considère comme la principale. » Google précise que les signaux canoniques permettent notamment d'indiquer la version préférée d'une page parmi plusieurs URL similaires, mais que la canonical constitue un signal, et non une garantie absolue de la version qui sera retenue.

Pourquoi plusieurs URL peuvent-elles exister ?

Cela arrive très souvent. Les paramètres d'URL peuvent créer différentes variantes : /produit, /produit?couleur=rouge, /produit?taille=42. Un site e-commerce peut également utiliser des URL de tri, de filtrage ou de suivi. Le contenu principal peut rester identique ou très proche.

Analogie — Plusieurs chemins vers la même maison

💡 Analogie — Plusieurs chemins vers la même maison — Imagine une maison. Tu peux y arriver par plusieurs routes. La maison reste la même. Pour un moteur de recherche, plusieurs URL peuvent parfois jouer ce rôle : plusieurs chemins permettent d'accéder à un contenu similaire. La canonical revient à dire : « Cette adresse est celle que je considère comme l'adresse principale. »

La canonical n'est pas une redirection

C'est probablement la confusion la plus fréquente. Une redirection 301 envoie réellement l'utilisateur d'une URL vers une autre. Avec une canonical, l'utilisateur reste sur l'URL qu'il a demandée. La page indique simplement aux moteurs quelle URL est considérée comme la version principale.

La canonical n'empêche pas une page d'être explorée

Une autre erreur fréquente consiste à penser : « Si je mets une canonical vers une autre page, Google ne visitera plus cette URL. » Ce n'est pas le rôle de la canonical. La canonical sert à indiquer une préférence entre plusieurs URL. Elle ne remplace pas le robots.txt. Elle ne remplace pas non plus une redirection.

La canonical peut être auto-référente

Une page peut indiquer comme canonical sa propre URL. La page indique alors : « Cette URL est elle-même la version canonique. » C'est une configuration très courante.

La canonical doit pointer vers une URL pertinente

Si une page concerne les chaussures de randonnée, il ne faut pas mettre comme canonical une page consacrée aux ordinateurs simplement parce que tu veux « concentrer le SEO ». La canonical doit correspondre au contenu concerné.

Google peut choisir une autre URL

Même si tu définis une canonical, Google peut parfois sélectionner une autre URL comme canonique. Pourquoi ? Parce que la canonical est un signal parmi d'autres. Google analyse notamment les contenus, les redirections, les liens internes et d'autres éléments pour déterminer la version qu'il considère comme principale.

Les pièges à éviter :

  • ✗ Confondre canonical et redirection 301
  • ✗ Mettre une canonical vers une page sans rapport
  • ✗ Bloquer une URL dans robots.txt en pensant que cela suffit pour gérer sa canonicalisation
  • ✗ Mettre plusieurs URL canoniques contradictoires
  • ✗ Utiliser systématiquement la page d'accueil comme canonical
  • ✗ Penser que Google est obligé de suivre ta canonical
  • ✗ Oublier de vérifier les URL canoniques après une migration ou une modification du site

4 Exemple concret

Imaginons une boutique en ligne. Tu as cette page :

🔗 url.txt
https://exemple.fr/chaussures-randonnee

Mais différents paramètres peuvent produire :

🔗 urls.txt
https://exemple.fr/chaussures-randonnee?couleur=rouge
https://exemple.fr/chaussures-randonnee?tri=prix

Tu considères que l'URL principale est :

📄 code.html
<link rel="canonical" href="https://exemple.fr/chaussures-randonnee" />

L'idée est d'indiquer aux moteurs quelle URL représente la version principale du contenu. Mais attention. Si les variantes de filtrage proposent réellement des contenus différents et doivent elles-mêmes être indexées, la situation doit être étudiée plus précisément. La canonical n'est pas une solution automatique à tous les problèmes de paramètres.

5 Comment le mettre en pratique

1

Identifie les pages potentiellement similaires

Cherche notamment : les URL avec paramètres, les variantes de produits, les anciennes versions d'URL, les pages accessibles par plusieurs chemins, les versions avec ou sans certains paramètres de suivi.

2

Détermine l'URL principale

Pose-toi cette question : « Quelle URL représente réellement la version principale de ce contenu ? »

3

Vérifie la balise canonical

Dans le code HTML de la page, cherche : <link rel="canonical" href="..." />

4

Vérifie que l'URL est cohérente

La canonical doit pointer vers une URL pertinente et accessible. Évite de pointer vers une URL qui renvoie une erreur ou qui redirige inutilement.

5

Vérifie les liens internes

Si tu veux qu'une URL soit considérée comme principale, tes liens internes doivent autant que possible pointer directement vers cette URL.

6

Vérifie après une migration

Une modification de structure peut modifier automatiquement les canonical. Après une refonte ou une migration, vérifie toujours leur cohérence.

7

Ne considère pas la canonical comme une garantie

Une canonical est une indication importante. Mais les moteurs peuvent retenir une autre URL lorsqu'ils disposent de signaux différents ou considèrent qu'une autre version est plus appropriée.

7 Quiz — Vérifie que tu as compris

Question 1/4

Question 1 — À quoi sert principalement une balise canonical ?

A À indiquer l'URL considérée comme principale parmi plusieurs URL similaires
B À rediriger automatiquement les visiteurs
C À bloquer les robots
D À supprimer une page
💡 Bonne réponse : A. La canonical indique aux moteurs quelle URL tu considères comme la version principale d'un contenu.

Question 2 — Quelle est la différence entre une canonical et une redirection 301 ?

A Elles ont exactement le même fonctionnement
B Une 301 envoie l'utilisateur vers une autre URL, tandis que la canonical indique une préférence aux moteurs
C La canonical bloque les internautes
D La 301 sert uniquement aux images
💡 Bonne réponse : B. Une redirection 301 change la destination de l'utilisateur, tandis que la canonical fournit principalement un signal aux moteurs.

Question 3 — Google est-il obligé de respecter la canonical renseignée ?

A Oui, toujours
B Oui, si elle est dans le <head>
C Non, Google peut sélectionner une autre URL canonique
D Oui, uniquement sur les sites e-commerce
💡 Bonne réponse : C. La canonical constitue un signal et Google peut retenir une autre URL lorsqu'il considère qu'elle est plus appropriée.

Question 4 — Une canonical vers la page d'accueil est-elle une solution universelle ?

A Oui
B Oui, pour toutes les pages supprimées
C Non, la canonical doit correspondre au contenu concerné
D Oui, pour les sites de moins de 100 pages
💡 Bonne réponse : C. Une canonical doit pointer vers une version pertinente du même contenu ou d'un contenu très similaire.

8 Et après ?

La suite logique

Tu viens de terminer un autre morceau important du SEO technique.

Tu sais maintenant faire la différence entre trois situations :

404 : « Cette URL ne correspond pas à une ressource disponible. »

301 : « Cette ancienne URL a été déplacée vers une nouvelle adresse. »

Canonical : « Plusieurs URL peuvent représenter ce contenu, mais voici celle que je considère comme principale. »

Ces trois notions sont proches dans la pratique, mais elles répondent à des problèmes différents. Et c'est justement ce qui rend le SEO technique intéressant : Il ne suffit pas de savoir utiliser un outil. Il faut comprendre quelle information envoyer aux moteurs selon la situation.
