1 Accroche

Accompagner le changement permanent d'une URL

Tu as une ancienne URL : /blog/ancien-article. Mais tu veux maintenant utiliser : /blog/nouvel-article.

Tu pourrais simplement supprimer l'ancienne page. Mais que se passe-t-il lorsqu'un internaute utilise encore l'ancienne adresse ? Il tombe sur une erreur 404. Et si Google ou d'autres sites possèdent encore des liens vers l'ancienne URL ? Ces liens continuent également à pointer vers une adresse qui n'est plus la bonne.

C'est là qu'une redirection 301 peut être utile. Elle permet d'indiquer que l'ancienne URL a été déplacée de manière permanente vers une nouvelle adresse.

3 Le concept expliqué simplement

Qu'est-ce qu'une redirection 301 ?

Une redirection 301 est une réponse HTTP indiquant qu'une ressource a été déplacée de manière permanente vers une autre URL.

Par exemple :

📄 code.txt
Ancienne URL : /blog/ancien-article
            ↓
           301
            ↓
Nouvelle URL : /blog/nouvel-article

Lorsqu'un utilisateur demande l'ancienne adresse, le serveur lui indique qu'il doit aller vers la nouvelle. Le navigateur suit alors la redirection.

Pourquoi « 301 » ?

Le nombre 301 correspond au code de statut HTTP utilisé pour signaler un déplacement permanent. Tu peux rencontrer d'autres codes de redirection, comme 302, qui correspond à une redirection temporaire. Dans ce chapitre, concentre-toi surtout sur la 301 : 301 = déplacement permanent.

Analogie — Le déménagement

💡 Analogie — Le déménagement — Imagine une entreprise qui déménage. Elle quitte « 10 rue des Lilas » pour s'installer « 25 rue des Roses ». Elle peut simplement disparaître de l'ancienne adresse. Mais elle peut aussi laisser un message : « Nous avons déménagé. Retrouvez-nous au 25 rue des Roses. » La redirection 301 joue un rôle similaire. Elle indique : « Cette ancienne adresse a changé. Voici la nouvelle. »

Quand utiliser une 301 ?

Une redirection 301 peut être pertinente lorsqu'une URL change définitivement. Par exemple : modification de la structure des URL, changement de nom d'un article, suppression d'une page remplacée par une autre pertinente, migration d'un domaine, passage d'une ancienne URL vers une nouvelle version.

La 301 ne sert pas à tout

Tu ne dois pas créer une 301 simplement parce qu'une URL existe. Si une page n'a aucune nouvelle destination pertinente, une 404 peut parfois être la bonne réponse. La question à te poser est : « Existe-t-il une nouvelle URL qui remplace réellement cette ancienne ressource ? » Si oui, une redirection peut être pertinente.

Les redirections ont un intérêt SEO

Lorsqu'une page est déplacée, une redirection correctement mise en place permet notamment aux moteurs de comprendre la relation entre l'ancienne et la nouvelle URL. Google indique que les redirections permanentes peuvent être utilisées pour signaler qu'une page a changé d'adresse et pour transférer les signaux associés à l'ancienne URL vers la nouvelle, sous réserve des conditions et de la configuration du site. L'idée importante à retenir : Une redirection 301 permet d'accompagner proprement un changement d'URL.

Attention aux chaînes de redirections

Imagine :

📄 code.txt
URL A
  ↓
 301
URL B
  ↓
 301
URL C

Tu as créé une chaîne de redirections. Le navigateur doit passer par plusieurs étapes avant d'arriver à la destination finale. Lorsque c'est possible, mieux vaut généralement faire une redirection directe de l'URL A vers l'URL C.

Attention aux boucles de redirection

Une situation encore plus problématique :

📄 code.txt
URL A
  ↓
URL B
  ↓
URL A

Le navigateur tourne en rond. C'est une boucle de redirection. La page ne peut alors pas être correctement chargée.

Les pièges à éviter :

  • ✗ Rediriger toutes les anciennes URL vers la page d'accueil
  • ✗ Créer des chaînes de redirections inutiles
  • ✗ Créer des boucles de redirection
  • ✗ Utiliser une 301 alors qu'aucune nouvelle page pertinente n'existe
  • ✗ Oublier de mettre à jour les liens internes
  • ✗ Multiplier les redirections au fil des années sans nettoyer les anciennes

4 Exemple concret

Imaginons un article :

🔗 url.txt
/blog/seo-pour-debutant

Tu décides de modifier son URL :

🔗 url.txt
/blog/guide-seo-debutant

Tu mets en place une redirection 301 :

📄 redirection.txt
/blog/seo-pour-debutant
            ↓
           301
            ↓
/blog/guide-seo-debutant

Un internaute qui utilise l'ancienne URL arrive alors sur la nouvelle. Les moteurs disposent également d'un signal indiquant que le déplacement est permanent. Tu peux ensuite mettre à jour les liens internes pour qu'ils pointent directement vers la nouvelle URL.

5 Comment le mettre en pratique

1

Identifie l'ancienne URL

Note précisément l'adresse qui doit disparaître.

2

Identifie la nouvelle URL

Choisis la page qui remplace réellement l'ancienne. Elle doit être pertinente.

3

Crée la redirection 301

Selon ton environnement, tu peux utiliser : une extension SEO, le système de gestion des redirections de ton hébergeur, la configuration du serveur, une solution adaptée à ton CMS.

4

Teste l'ancienne URL

Ouvre l'ancienne adresse. Elle doit conduire vers la nouvelle URL.

5

Mets à jour tes liens internes

Même si la redirection fonctionne, il est préférable que tes propres liens pointent directement vers la nouvelle URL.

6

Vérifie les chaînes

Si une ancienne URL redirige déjà vers une autre URL, vérifie que tu ne crées pas inutilement plusieurs étapes.

7

Surveille après migration

Après une modification importante des URL, vérifie les erreurs et les redirections dans tes outils SEO et d'analyse.

7 Quiz — Vérifie que tu as compris

Question 1/4

Question 1 — Que signifie le code HTTP 301 ?

A Page introuvable
B Déplacement permanent
C Accès interdit
D Serveur indisponible
💡 Bonne réponse : B. Le code 301 indique qu'une ressource a été déplacée de manière permanente.

Question 2 — Quand une redirection 301 est-elle particulièrement pertinente ?

A Lorsqu'une page a été déplacée vers une nouvelle URL pertinente
B Pour toutes les URL inexistantes
C Pour sécuriser une page
D Pour accélérer une image
💡 Bonne réponse : A. La 301 est notamment utilisée lorsqu'une ressource a changé définitivement d'adresse.

Question 3 — Qu'est-ce qu'une chaîne de redirections ?

A Plusieurs URL qui se redirigent successivement avant d'atteindre la destination finale
B Plusieurs pages identiques
C Une liste de liens internes
D Un fichier robots.txt
💡 Bonne réponse : A. Une chaîne correspond à plusieurs redirections successives avant d'arriver à la destination finale.

Question 4 — Pourquoi éviter de créer inutilement des chaînes de redirections ?

A Parce qu'elles peuvent ajouter des étapes inutiles avant d'atteindre la page finale
B Parce qu'elles empêchent toujours l'indexation
C Parce qu'une URL ne peut jamais être redirigée deux fois
D Parce qu'elles suppriment automatiquement les pages
💡 Bonne réponse : A. Il est préférable, lorsque c'est possible, de rediriger directement l'ancienne URL vers la destination finale.

8 Et après ?

La suite logique

Tu sais maintenant comment accompagner le déplacement permanent d'une page.

Mais il existe une autre situation très fréquente. Imagine que deux URL différentes donnent accès à un contenu identique ou très similaire. Par exemple : https://exemple.fr/produit et https://exemple.fr/produit?couleur=rouge.

Comment indiquer aux moteurs quelle URL doit être considérée comme la version principale ?

C'est là qu'intervient la balise canonical.
