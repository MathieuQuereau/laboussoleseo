Le hreflang, pour les sites multilingues

1 Accroche

Gérer les différentes versions linguistiques de tes pages

Imagine que ton entreprise possède un site en français et en anglais.

Tu as une page : https://exemple.fr/chaussures-randonnee et sa version anglaise : https://exemple.com/hiking-shoes. Les deux pages parlent du même produit. Mais elles s'adressent à des publics différents.

Comment indiquer aux moteurs de recherche qu'il existe plusieurs versions de cette même page ? C'est notamment le rôle du hreflang. Cette information permet d'indiquer les différentes variantes linguistiques ou régionales d'une page. Et dès que tu travailles sur un site multilingue, cette notion devient particulièrement importante.

3 Le concept expliqué simplement

Qu'est-ce que le hreflang ?

Le hreflang est une annotation qui permet d'indiquer aux moteurs de recherche les différentes versions linguistiques ou régionales d'une page.

Google recommande notamment d'utiliser ces annotations lorsqu'un site possède plusieurs versions d'une page destinées à différentes langues ou régions.

Par exemple :

📄 code.html
<link rel="alternate" hreflang="fr" href="https://exemple.fr/page" />
<link rel="alternate" hreflang="en" href="https://example.com/page" />

Cela indique qu'il existe une version française et une version anglaise de la page.

Pourquoi en a-t-on besoin ?

Imagine que Google dispose de deux pages : Page A en français et Page B en anglais. Sans information supplémentaire, le moteur doit comprendre par lui-même la relation entre ces versions. Le hreflang fournit un signal explicite.

Analogie — Le panneau indicateur

💡 Analogie — Le panneau indicateur — Imagine une gare internationale. Tu as plusieurs trains : Paris → Français, London → English, Madrid → Español. Le hreflang joue un peu le rôle des panneaux qui indiquent : « Cette direction correspond à tel public. »

Le code de langue

Le premier élément important est le code utilisé dans hreflang. Par exemple : fr pour le français ou en pour l'anglais.

Tu peux également combiner une langue avec une région. Par exemple : en-GB pour l'anglais destiné au Royaume-Uni et en-US pour l'anglais destiné aux États-Unis. Cela permet de distinguer des variantes régionales.

Langue et région, ce n'est pas la même chose

Imagine deux pages : Français pour la France et Français pour la Belgique. La langue est identique. Mais le contenu peut être différent : monnaie, livraison, adresse, produits disponibles, informations commerciales, expressions utilisées.

Le hreflang peut donc aussi servir à distinguer des versions régionales.

Les versions doivent se référencer mutuellement

C'est un point très important. Si ta page française indique qu'elle possède une version anglaise, la page anglaise doit également indiquer la version française.

Google recommande que chaque version liste elle-même ainsi que les autres variantes.

Par exemple :

Page française :

📄 code.html
<link rel="alternate" hreflang="fr" href="https://exemple.fr/page" />
<link rel="alternate" hreflang="en" href="https://example.com/page" />

Page anglaise :

📄 code.html
<link rel="alternate" hreflang="fr" href="https://exemple.fr/page" />
<link rel="alternate" hreflang="en" href="https://example.com/page" />

x-default

Tu peux également rencontrer x-default. Cette valeur permet d'indiquer une version par défaut pour les utilisateurs qui ne correspondent pas aux versions explicitement définies.

Par exemple :

📄 code.html
<link rel="alternate" hreflang="x-default" href="https://example.com/page" />

Le hreflang ne traduit pas ta page

C'est important. Ajouter hreflang="en" ne transforme pas une page française en anglais. Le contenu doit réellement exister dans la langue correspondante. Le hreflang sert à indiquer la relation entre les différentes versions.

Le hreflang ne détecte pas automatiquement la langue

Autre nuance importante : Google indique que le hreflang n'est pas utilisé pour détecter directement la langue d'une page. Le moteur utilise ses propres systèmes pour déterminer la langue du contenu. Le hreflang sert surtout à lui signaler les variantes que tu souhaites associer.

Les pièges à éviter :

  • ✗ Utiliser le hreflang sur un site qui n'a qu'une seule version linguistique sans raison
  • ✗ Indiquer une mauvaise URL
  • ✗ Oublier de faire référence à la page elle-même
  • ✗ Créer des annotations qui ne sont pas réciproques
  • ✗ Confondre langue et région
  • ✗ Croire que hreflang traduit automatiquement une page
  • ✗ Utiliser des codes de langue incorrects

4 Exemple concret

Imaginons une entreprise qui vend des chaussures en France, au Royaume-Uni et aux États-Unis.

Elle possède trois versions :

🔗 urls.txt
https://exemple.fr/chaussures-randonnee
https://example.co.uk/hiking-shoes
https://example.com/hiking-shoes

La version française peut contenir :

📄 code.html
<link rel="alternate" hreflang="fr-FR" href="https://exemple.fr/chaussures-randonnee" />
<link rel="alternate" hreflang="en-GB" href="https://example.co.uk/hiking-shoes" />
<link rel="alternate" hreflang="en-US" href="https://example.com/hiking-shoes" />
<link rel="alternate" hreflang="x-default" href="https://example.com/hiking-shoes" />

L'objectif est de permettre aux moteurs de comprendre qu'il existe plusieurs variantes adaptées à différents publics.

Google précise que les annotations peuvent être ajoutées via le HTML, les en-têtes HTTP ou un sitemap. Ces méthodes sont considérées comme équivalentes pour Google.

5 Comment le mettre en pratique

1

Liste les versions de tes pages

Commence par identifier : la version française, la version anglaise, la version espagnole, les éventuelles variantes régionales.

2

Identifie les codes adaptés

Par exemple : fr, en, es, de. Ou avec une région lorsque c'est nécessaire : fr-FR, fr-CA, en-US, en-GB.

3

Fais correspondre les URL

Chaque version doit pointer vers la bonne URL.

4

Ajoute les annotations

Tu peux notamment utiliser le <head> de tes pages :

<link rel="alternate" hreflang="fr" href="https://exemple.fr/page" />

<link rel="alternate" hreflang="en" href="https://example.com/page" />

5

Vérifie la réciprocité

Si la version française référence l'anglaise, vérifie que l'anglaise référence également la française.

6

Vérifie les URL

Les URL doivent être complètes et pointer vers les bonnes pages.

7

Évite les systèmes inutilement complexes

Google permet plusieurs méthodes : balises HTML, en-têtes HTTP, sitemap. Choisis une méthode que tu peux réellement maintenir correctement.

7 Quiz — Vérifie que tu as compris

Question 1/4

Question 1 — À quoi sert principalement le hreflang ?

A À traduire automatiquement une page
B À indiquer les différentes versions linguistiques ou régionales d'une page
C À accélérer un site
D À empêcher Google d'explorer une page
💡 Bonne réponse : B. Le hreflang permet d'indiquer aux moteurs les différentes variantes linguistiques ou régionales d'une page.

Question 2 — Que signifie en-GB ?

A Français pour la Belgique
B Anglais pour le Royaume-Uni
C Anglais pour les États-Unis
D Espagnol pour le Royaume-Uni
💡 Bonne réponse : B. en-GB correspond à l'anglais ciblant le Royaume-Uni.

Question 3 — Une page française doit-elle référencer sa propre version avec hreflang ?

A Non
B Oui, chaque version doit notamment se référencer elle-même
C Seulement si elle possède plus de trois langues
D Uniquement sur WordPress
💡 Bonne réponse : B. Google recommande que chaque version liste elle-même ainsi que les autres variantes.

Question 4 — Le hreflang traduit-il automatiquement une page ?

A Oui
B Oui, uniquement en anglais
C Non, il indique simplement la relation entre les différentes versions
D Oui, si x-default est utilisé
💡 Bonne réponse : C. Le hreflang ne traduit pas le contenu. Il indique aux moteurs quelles versions linguistiques ou régionales existent.
